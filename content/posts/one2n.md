## 题目要求

编写一个名为 `one2n` 的命令，接收一个大于 0 的整数 n，计算 1+2+3+…+n 的结果并打印；当不接任何参数时，打印其用法。

## 脚本实现

新建文件并写入：

```bash
#!/bin/bash
# one2n：计算 1+2+...+n

if [ $# -ne 1 ]; then
    echo "用法：$0 正整数n"
    exit 1
fi

n=$1

# 参数合法性检查
if ! [[ "$n" =~ ^[0-9]+$ ]] || [ "$n" -le 0 ]; then
    echo "错误：参数必须是大于 0 的整数"
    exit 1
fi

sum=0
for ((i = 1; i <= n; i++)); do
    sum=$((sum + i))
done

echo "1+2+...+$n = $sum"
```

赋予执行权限：

```bash
chmod +x one2n
```

## 验证

```bash
./one2n            # 不带参数，打印用法
./one2n 10         # 输出 1+2+...+10 = 55
./one2n 100        # 输出 1+2+...+100 = 5050
./one2n 0          # 参数非法，提示错误
```

## 三种执行方式的区别

- `./one2n`：把脚本当作可执行文件运行，需要脚本有执行权限（`chmod +x`），内核按 shebang 指定的解释器启动，**在新子 shell 中执行**。
- `bash one2n`：显式指定用 bash 解释脚本，不需要执行权限，同样**在子 shell 中执行**。
- `source one2n`：在**当前 shell** 中逐行执行脚本内容，不新建子进程，所以脚本里定义的变量、修改的目录在当前终端中依然有效；脚本若是 `exit`，会直接退出当前终端。

三者对比如下：`./one2n` 与 `bash one2n` 效果基本等价（前者依赖执行权限与 shebang，后者不依赖），`source` 影响的是当前 shell 环境。

## 遇到的问题与解决办法

1. `./one2n: Permission denied`：忘记 `chmod +x`，或改用 `bash one2n` 执行。
2. 未做参数检查时，直接运行 `./one2n` 报 `unary operator expected`：`[ $# -ne 1 ]` 中未加引号遇到空参数会语法错误，补充参数判断后可正常提示用法。
3. 输入非数字时 `for` 循环报错：增加正则 `^[0-9]+$` 校验，提前拦截非法输入。

## 小结

`$#`、`$1`、`$0` 是脚本接收参数的基础：`$#` 为参数个数、`$1` 为第一个参数、`$0` 为脚本名。加上参数个数检查与合法性校验，脚本才能从"能跑"变成"可靠"；而 `./`、`bash`、`source` 三种执行方式的选择，本质上是在决定"是否新建子 shell"。
